# Public assistant redesign and verification

The pre-change audit is `chatbot-audit.md`. The replacement stays under `frontend/src/marketing/chat`; authenticated intake, Shopping, Broker, StaffConsole, servicing and payments were not changed for this widget.

Use `VITE_NEXT_CHAT_UI=true` for preview/build QA; it is on by default in development and off by default in a production build unless explicitly enabled. `false` keeps the prior `ChatPanel`. The flag is checked by the existing launcher. The greeting/robot artwork remains, with lazy dotLottie, visibility handling and reduced-motion fallbacks. The new panel loads only after first open. The checked-in environment example and CI enable the flag explicitly.

Scoped tokens use deep navy, soft white and subtle teal accents, with a navy variant for dark mode. The rounded composer has one shared focus ring, consistent 44px icon buttons, a borderless textarea and compact disclosure links. Desktop supports 400px and expanded 560px panels. Mobile uses a safe-area-aware viewport sheet with `visualViewport` keyboard adjustment and 16px input text. Arabic mirrors layout using logical properties and `dir=auto` content. Dark/reduced-motion modes have distinct checks. Body text is 15/22px; composer grows to six lines. Actions have accessible names and visible focus. The dialog remains non-modal without a keyboard trap. Closing restores launcher focus.

Messages include timestamps, delivery/error state, copy, local helpful/not-helpful feedback, regenerate, starter/follow-up prompts and trusted internal actions. Safe CommonMark uses `react-markdown` and `rehype-sanitize`; a bounded text-only pipe-table renderer avoids the heavier GFM autolink/footnote bundle. No HTML, executable links or remote markdown images are rendered. A slim scrollbar and near-bottom tracking preserve the reader's scroll position. Conversation state retains the latest 200 messages in sessionStorage; raw files/audio and object URLs are not persisted. New conversation has confirmation and Undo until another message is sent. TXT transcript download is local.

SSE uses `fetch`/ReadableStream, UTF-8 buffering, frame-batched text and AbortController Stop. It streams the existing **reviewed deterministic guidance**, not live model tokens. The response metadata states that distinction. Stop preserves partial text; regenerate resends the last question. A 404/405/501 stream route falls back to the existing POST endpoint without silently discarding attachments or shortening long text. Errors, retry/human path, offline composer, rate-limit timer and progress/recovery states are present. Messages are not sent automatically on reconnection.

File upload supports MIME plus decoded-content validation for PDF/JPG/PNG/WebP/HEIC, 10 MB/file, five attachments/message, bounded PDF pages/pixels, drag/drop, pasted images, camera selection, progress and removal. PDFs use local text extraction; images need local Tesseract OCR. If OCR is unavailable, a clear 503 asks for text/PDF input; no vision model is falsely claimed. Identity/payment text is rejected. Raw bytes are discarded after processing. Temporary extracted text lives only in bounded process memory, is consumed once or deleted explicitly, and is swept every 30 seconds within the configured maximum retention. Restarts discard it. No file contents enter application logs or an external LLM. The assistant does not authenticate policy wording or decide personal coverage from a document.

Voice uses feature-detected Web Speech recognition with editable interim text. With informed consent, browsers without that API can record via MediaRecorder and call Groq transcription. Recordings are decoded/limited to 60 seconds/10 MB, never stored by Helm, and all tracks stop on cancel/close/unmount. Provider configuration failures return a typing fallback. Consent precedes either provider path. The optional auto-send/read-aloud/emoji features were not enabled. Groq model availability was checked against its [speech documentation](https://console.groq.com/docs/speech-to-text); optional research extraction follows its [JSON output documentation](https://console.groq.com/docs/structured-outputs).

Human handoff reuses UK support references. The form collects a topic, not unusable callback details, because this demo has no connected email/callback delivery. This deliberate privacy adaptation replaces the brief's contact-field suggestion. All screens say no live response is promised. No message was sent to a person. Feedback stays in the browser; no training pipeline is implied.

The chat brief's UAE copy was replaced with UK wording to match the current site and the newer UK-only research spec. Arabic has translated interface/general-topic copy and fixed safety/topic routing; detailed unsupported topics explicitly fall back to reviewed English guidance. Translation and medical/regulatory wording still need independent language review before a real service.

## QA evidence and boundaries

Screenshots and axe outputs are in `docs/chatbot-screenshots`. The recording screenshot uses a **simulated** browser recognition API. It proves control behavior, not microphone accuracy. Browser checks cover desktop empty/conversation, export/refresh/undo, focus restoration, PDF upload, Stop, offline recovery, fallback, mobile Arabic/dark/reduced-motion and the research comparison flow. Sanitization, table rendering, fragmented UTF-8 SSE and interrupted/fallback streams have unit tests.

The chat JS/CSS build addition measured about 53 KB gzipped excluding Lottie, below 60 KB. Remaining manual QA: actual Chrome/Edge/Safari/Firefox microphones and permission UI, iOS/Android keyboards/camera, 200% text/400% zoom, real screen readers, independent Arabic review and a deployed OCR/transcription environment. No actual-device or human-testing sign-off is claimed. Legacy production blockers remain unchanged.
